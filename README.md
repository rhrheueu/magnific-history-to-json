# Magnific History to JSON

**Версия 2.1** · [Скачать расширение](https://github.com/rhrheueu/magnific-history-to-json/releases/latest/download/magnific_history2json.zip) · [Инструкция PDF](https://github.com/rhrheueu/magnific-history-to-json/releases/latest/download/magnific_history2json_guide_ru.pdf)

Chrome-расширение для выгрузки общей истории Magnific за точные даты отчёта. Результат — один ZIP с JSON и превью.

[Инструкция со скриншотами (PDF, 4 страницы)](docs/magnific_history2json_guide_ru.pdf).

## Установка

Распакуйте архив в постоянную папку, например `C:\Users\username\ChromeExtensions\magnific_history2json`. Имя ChromeExtensions — удобное соглашение для этой инструкции, не специальное требование Chrome. Папку после установки нельзя удалять или переносить.

В `chrome://extensions` включите Developer mode → Load unpacked → выберите папку с `manifest.json`. Закрепите иконку расширения.

Требуется Chrome 116+.

## Использование

1. Откройте `https://www.magnific.com/app/projects/all-assets` и войдите в нужный аккаунт.
2. Нажмите иконку расширения. Запуск из конкретного проекта автоматически переводит в All assets.
3. Проверьте два поля дат. По умолчанию: 21-е прошлого месяца — 20-е текущего включительно. Есть кнопка предыдущего отчётного периода; обе даты можно менять вручную.
4. Нажмите «Выгрузить». Календарь Magnific получает конкретные дни, месяц и год. Относительные фильтры Last month / Last 3 months не используются.
5. Во время сбора истории оставьте вкладку активной и окно видимым. Скрытая вкладка ставит сбор на паузу до возвращения.
6. На этапе «Собираю архив» можно переключаться: упаковка идёт отдельно от страницы. Готовый ZIP сохраняется автоматически в загрузки Chrome, без принудительного Save As и отдельных загрузок каждой картинки.

До наступления конечной даты сбор идёт по сегодня; окно предупреждает об этом, а JSON сохраняет `effective_end` и `period_in_progress`. Для уже завершённого периода используйте «Предыдущий отчёт» или свои даты.

Другие фильтры сайта (владелец, тип, статус) сохраняются и перечисляются перед стартом. Поддержаны `/ru/`, `/es/`, `/pt-br/` и другие языковые префиксы. На неправильной странице появляется активная ссылка на Magnific. Для защищённых служебных страниц Chrome открывается отдельная страница помощи.

## Содержимое архива

- `magnific_history_....json` — массив записей с промптами и параметрами;
- `previews/` — полученные превью;
- `uploads/` — превью загруженных изображений и видеореференсов, если они есть;
- `export_summary.json` — сводка сбора и ошибок.

Распаковывайте ZIP целиком: `images[].file` — путь относительно JSON. Один URL запрашивается и хранится один раз. Если URL встречался как загрузка и генерация одновременно, общий файл хранится в uploads/; роль сохраняется у каждой ссылки.

`images[].asset_kind`: `upload`, `generation` или `unknown`, если тип не определился. Нераспознанные элементы сохраняются; тип не угадывается. HTTP-ошибки и ответы HTML вместо картинки отмечаются в `note`. Это превью из истории, а не оригиналы генераций.

## Проверка активности вкладки в 2.1

При переключении на другую вкладку или сворачивании окна сбор истории ставится на паузу. При возврате продолжается с сохранённого места. Проверка учитывает состояние самой вкладки Chrome. На этапе сборки ZIP активность страницы уже не требуется.

## Группы и параметры

В версии 2.0 заголовок связывается только со своими последовательными строками картинок. Несколько строк одной группы сохраняются вместе; соседние группы не подставляются при виртуализации. `feed_group_index` — индекс группы в этой конкретной выгрузке, не постоянный ID проекта или генерации.

Модель берётся из тегов модели, а FPS, длительность и пропорции сохраняются отдельно в `parameters`. У загрузок модель пустая. `images[].media_type` отличает изображение от видеопревью; тип видео определяется по разметке карточки, а не по пустому alt у JPG. Исходные видео и аудио расширение не скачивает. Аудиозагрузки сохраняются как записи без изображения; их явный тип — `audio upload`.

## Диагностика

Обычный запуск сохраняет JSON с картинками. Диагностический JSON без картинок спрятан в Options → «Решение проблем», действует на один запуск и автоматически возвращается к картинкам. В обычном окне переключателя режима нет.

Stop завершает сбор досрочно с `export_status: stopped`. Ограничение числа итераций помечается `iteration_limit`. При ошибке упаковки на странице можно отдельно сохранить собранный JSON.

ZIP собирается в памяти, ограничен 4 ГБ и 65 534 файлами. Очень большие периоды можно разбивать точными датами. При работе в другом приложении окно Magnific должно оставаться видимым; полностью скрытое окно Chrome может приостановить сбор. Не допускайте сна компьютера до завершения.

## Точность дат и проектов

Фильтрацию периода выполняет штатный календарь Magnific; расширение проверяет подтверждение обеих границ. Если сайт показывает относительную подпись вроде Last 3 months, точные границы повторно проверяются в нативном календаре. Подписи `Today`, `2 months ago` и т.п. не используются для вычисления принадлежности к отчёту. `date_group` сохраняет только подпись интерфейса и не является точным временем создания каждой генерации. В JSON записан точный период отчёта, но не придуманные timestamps отдельных ассетов.

Автоматическая привязка каждого ассета All assets к проекту пока не реализована. В detail view есть «Saved in»; для заполнения проекта у каждого ассета нужен дополнительный обход карточек.

## Разработка

`background.js` запускает `report.js` и `parser.js`, управляет настройками и загрузкой. `report.js` задаёт даты и проверяет календарь. `parser.js` собирает виртуальную ленту. `offscreen.html` / `offscreen.js` и `zip.js` формируют архив. `start.html` — помощь при запуске с неподходящей страницы.

Проверки: `node --test tests/*.test.js` (Node 20+, Python 3 для независимой проверки ZIP). Сборка: `python3 scripts/package.py`.

[Проверенный набор сценариев](docs/VALIDATION.md). Рабочие выгрузки и личные генерации в репозиторий и дистрибутив не включаются.
